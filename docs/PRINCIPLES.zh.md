## 1. 这玩意儿到底解决什么问题？

Claude Code（下文统一叫 cc）在终端跑的时候，输入框上方那条状态行**默认是空的**。它不会告诉你：

- 当前会话烧了多少 token
- 你的订阅额度还剩多少
- 当前会话花了多少钱
- 离 5 小时窗口重置还有多久

要看这些得敲 `/cost`、`/usage` 等命令。**烦**。

这个项目让你**永远在屏幕底部看到这些数据**——cc 每次状态行刷新都更新一次，不用敲任何命令。

---

## 2. 它怎么做到「不改 cc 程序也能加功能」？

关键词：**扩展点**（extension point）。

🏠 **类比**：你家门上有一个**信箱口**。邮递员从外面塞信进来，你从里面收。
- 邮递员不用进屋
- 你不用拆门
- 信箱口是房子设计时**故意留的接口**

cc 也有这种"信箱口"。它在自己源码里**预留了一些位置**，说："这里如果你想自定义，告诉我一声，我把数据塞给你。"

这些预留位置叫**扩展点**或**钩子（hook）**。`statusLine` 就是其中一个——它是为「状态行」这块 UI 预留的信箱口。

> 💡 很多人以为给软件加功能必须"改源码"。其实成熟软件都会预留一堆扩展点：
> - bash 的 `PS1`（命令提示符）
> - vim 的 `~/.vimrc`
> - tmux 的 `status-format`
> - VS Code 的 extensions API
>
> 全是同一个套路。

## 3. statusLine 是怎么工作的？

cc 启动时会读一个文件：`~/.claude/settings.json`。这是 **cc 的配置中心**。

我们在里面加了这么一段：

```json
"statusLine": {
  "type": "command",
  "command": "$HOME/.claude/statusline.py"
}
```

意思是："cc 你好，每次要刷新状态行的时候，请去执行 `~/.claude/statusline.py`，然后把它的输出贴到状态行上。"

cc 看到这段就**记下来**。之后每次它要刷新状态行，就会：

```
1. cc 在内存里有当前所有状态
   (模型、cost、上下文用量、订阅额度……)
   ↓
2. cc 把这些状态打包成一段 JSON
   ↓
3. cc 启动一个子进程跑你指定的脚本
   (~/.claude/statusline.py)
   ↓
4. cc 把那段 JSON 通过【管道】灌到脚本的 stdin
   ↓
5. 脚本读完，算出一行字符串，写到 stdout
   ↓
6. 脚本退出
   ↓
7. cc 读到脚本的 stdout，把它当成状态行渲染
```

整个过程**几毫秒**就完了。

## 4. 等等，啥是 stdin / stdout / 管道？

🏭 **类比**：每个程序都是个**小工厂**，工厂有三个门：

```
        ┌────────────────┐
 入料 → │                │ → 出料
(stdin) │    程序        │ (stdout)
        │                │
        │                │ → 报错口
        └────────────────┘ (stderr)
```

- **stdin** = 入料口（standard input）
- **stdout** = 出料口（standard output）
- **stderr** = 报错口（standard error）

**「管道」（pipe）就是把 A 工厂的出料口接到 B 工厂的入料口**：

```bash
echo "hello" | wc -c
```

- `echo "hello"` 把字符串写到自己的 stdout
- `|` 是管道符，把它接到下一个程序的 stdin
- `wc -c` 从 stdin 读，数字符数，打印 `6` 到自己的 stdout

cc 调用我们脚本的时候，就是用管道把它准备的 JSON 灌进脚本的 stdin。脚本写到 stdout 的内容被 cc 收走当状态行。

## 5. 我们的脚本到底干啥？

骨架就 3 行：

```python
import json, sys
data = json.load(sys.stdin)          # 读 cc 喂的 JSON
print(f"$ {data['cost']['total_cost_usd']:.2f}")  # 写一行字符串
```

完事。

我们 ~300 行的版本，不过是把这 3 行**装饰**成：

- 多解析几个字段（cost / 上下文用量 / 订阅额度 / 工作目录…）
- 加颜色码（ANSI escape，比如 `\033[32m` 是绿色）
- 画进度条（`█░░░░░░░`）
- 时间格式化（`4h12m`）
- 支持 `--columns=` 让你挑要显示哪几列
- 加 fallback（老版本 cc 没有某些字段时去解 JSONL 自己算）

但骨架还是那 3 行：**读 stdin → 算 → 写 stdout → 退出**。**没有后台进程、没有持久状态、没有任何网络请求**。下次再被叫起时，从零开始。

## 6. 数据是怎么到 cc 内存里的？

我们脚本读到的 `cost` / `rate_limits` / `context_window` 等等，是 cc **自己产出**的。它的来源：

```
你发一条消息
    │
    ▼
cc 向 Anthropic API 发请求
    │
    ▼
Anthropic 响应里夹带：
  · 这次用了多少 token
  · 你订阅的 5h 窗口已用 38%
  · 你订阅的 7d 周用量已用 18%
  · 各窗口什么时候重置
    │
    ▼
cc 解析响应，把这些数字存到自己内存的一个变量里
    │
    ▼
cc 刷新状态行时，把内存里的当前快照打包成 JSON
    │
    ▼
cc 通过管道灌给我们的脚本
    │
    ▼
我们渲染
```

### 两个关键点

**1. `rate_limits` 只存在 cc 进程的内存里**，不写盘。`/exit` cc 之后就没了。下次起新会话，**发第一条消息之前**这个字段在 stdin payload 里**根本不存在**（因为还没收到任何 API 响应）。我们的脚本对此有判空处理（5h/7d 两列自动不显示）。

**2. 我们没替 cc 调任何 API**。我们白嫖了 cc 本来就在做的事。这是为什么 terminal 端这个项目很优雅——而桌面客户端要做同样的事就难得多（cc 帮我们办了所有脏活）。

---

## 7. `context_window` 和 `rate_limits` 是两回事

| 概念 | 单位 | 含义 | 什么时候有 |
| --- | --- | --- | --- |
| `context_window` | token | **当前对话**塞进模型脑子里的内容有多少。模型脑子的上限叫"上下文窗口"，Opus 4.7 的 1M 版本就是 100 万 token | 几乎一直有 |
| `rate_limits` | 百分比 | **你订阅套餐**剩余多少额度。分 5 小时窗口和 7 天周用量两个维度 | 只有订阅用户、且首次 API 请求之后 |

两者的关系：你每发一条消息，会**同时**：
- 增加 `context_window` 占用（这一轮塞了更多东西给模型）
- 消耗 `rate_limits`（订阅额度被啃掉一点）

但**它们的比例不固定**——上下文用得多不等于订阅消耗得多。一个长会话如果 cache 命中率高，可以很便宜地烧很多 token。所以两个数都要看：

- `ctx 24% (237k)` 告诉你：当前对话离爆窗（模型脑容量上限）还远
- `5h 38%` 告诉你：你订阅额度被啃了 38%

## 8. 为什么这不是 patch？

「patch」字面意思是「补丁」——改人家程序的源码。

我们实际改了什么：

```diff
  /Applications/Claude.app/         ← cc 程序本体，一行没动
  /Users/<you>/.local/share/claude/ ← cc 二进制，一行没动

  ~/.claude/settings.json:
+   "statusLine": { ... }           ← 加了 4 行配置
                                      （这文件本来就是给用户写的）

+ ~/.claude/statusline.py           ← 全新的用户脚本
```

这不是 patch，这是**用 cc 自己留好的扩展点**。就像 bash 没被 patch，你也能自定义命令提示符——因为它本来就让用户在 `.bashrc` 里写 `PS1`。

更准确的术语是 **plugin** / **extension** / **consumer of an extension point**。

> repo 名里有 "patch" 是历史原因（一开始项目目录叫 `claude_code_patch`）。但本质上它是个 plugin。

## 10. 拓展：statusLine 只是 cc 众多扩展点之一

`settings.json` 里能写好几种 key，每种对应不同的事件 / 接口：

| key | 性质 | 干什么的 |
| --- | --- | --- |
| `statusLine` | 单一事件 | 状态行刷新（**我们用的**） |
| `hooks` | 9 个事件 | 工具调用前后、用户发消息时、会话结束时等 |
| `apiKeyHelper` | 单一接口 | API key 由用户脚本动态提供 |
| `mcpServers` | 声明 | 启动时拉起哪些 MCP 工具服务 |
| `permissions` | 规则 | 哪些操作 allow / deny / ask |
| `outputStyle` | 选项 | 选预设输出风格 |
| `env` | 注入 | 给所有 spawn 的子命令注入环境变量 |

`hooks` 又细分成 9 个具体事件，每个都能让你**改变 cc 的行为**（不只是显示）：

| `hooks.<event>` | 何时触发 | 能干预？ |
| --- | --- | --- |
| `UserPromptSubmit` | 你按回车发消息时 | ✅ 能改写 / 拦截 |
| `PreToolUse` | 工具要调用，还没真调 | ✅ 能阻止 / 改输入 |
| `PostToolUse` | 工具调完了 | ✅ 能给模型加额外提示 |
| `Notification` | cc 想推系统通知 | ✅ 能重定向到 Slack 等 |
| `Stop` / `SubagentStop` | 模型回应完 / 子 agent 完 | 通常只观察 |
| `PreCompact` | 上下文压缩之前 | 通常只观察 |
| `SessionStart` / `SessionEnd` | 会话开始 / 结束 | 通常只观察 |

**精髓**：cc 是按 key 来分发的**「发布-订阅」机制**。你写哪个 key，就订阅哪个事件。没写就完全不发生，零开销。

> 想看 hooks 能玩出什么花样，搜「claude code hooks」官方文档，或者翻这个 repo 后续可能加的 `docs/HOOKS-IDEAS.md`。

## 11. 词汇表

| 词 | 解释 |
| --- | --- |
| **stdin / stdout / stderr** | 程序的标准输入 / 输出 / 报错通道 |
| **管道 (pipe)** | 把 A 的 stdout 接到 B 的 stdin 的连接符（`\|`） |
| **ANSI escape code** | 终端里控制颜色 / 样式的特殊字符序列（如 `\033[32m` = 绿色） |
| **token** | 模型处理文本的最小单位。1 个 token ≈ 0.7 个英文单词 / 0.5 个汉字 |
| **上下文窗口** | 模型一次能"看到"的最大 token 数量 |
| **prompt cache** | 复用之前请求的内容，1 折计费的机制 |
| **rate limit** | 订阅套餐的额度限制（5h 窗口 + 7d 周用量） |
| **extension point / hook** | 程序预留的"信箱口"，让用户接入自己的代码 |
| **JSON / JSONL** | 数据格式 / 每行一条 JSON 的文件格式（JSON Lines） |
| **process / spawn** | 进程 / 启动子进程 |

## 12. 自己改？

脚本零外部依赖（只用 Python 3 标准库）。常见修改入口：

| 想改什么 | 改 `statusline.py` 哪里 |
| --- | --- |
| 加新列 | 写一个 `col_xxx(c)` 函数，注册到 `COLUMNS` dict |
| 改颜色阈值 | `pick_color` 函数的 `scale=(50.0, 80.0)` |
| 改分隔符 | `DEFAULT_SEP` 常量，或运行时传 `--sep=` |
| 加新模型窗口 | `CONTEXT_LIMITS` dict（cc v2+ 优先用 stdin payload 里的，这个表只对老版本生效） |

**调试不用进 cc**——直接拿个 JSON 文件 `cat sample.json | ./statusline.py` 就能跑。这就是 stdin 设计带来的开发体验。

## 13. 一句话总结

```
cc 在自己的内存里已经有所有你想看的数据。
我们没改 cc，只是让它在刷状态行时调一下我们的脚本，
顺便把那段数据通过管道喂过来。
我们写一行字符串回去，它就显示在状态行上。
```

整个项目本质就是一个 **30 行 stdin → stdout 过滤器**，剩下的都是装饰。
